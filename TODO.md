## High-priority audit findings (2026-09-28)

### P1 - Correctness and recovery

- [x] **Treat a deleted target as completed cleanup instead of leaving the zone permanently stuck.** Missing target Actors and already-absent Items now complete cleanup, while genuine Item deletion failures retain their records for retry. `deleteToken` and `deleteActor` hooks proactively reconcile stale applied records, including every embedded Item record for a deleted unlinked Token's synthetic Actor. Regression coverage includes deletion before exit cleanup and before zone dismissal. Code: [runtime.js](scripts/runtime.js).

- [x] **Only start condition-recovery immunity when the watched condition was actually applied.** Outcome application now records exact created/reused Condition Item IDs separately from the general affected result. Recovery watchers require the configured condition in the resolved outcome and a live matching Item, then follow that specific Item until it ends; legacy slug-only watchers remain compatible. Validation also requires the recovery condition in at least one active outcome. Code: [runtime.js](scripts/runtime.js), [zone-config.js](scripts/zone-config.js).

- [x] **Make save delivery recoverable when chat creation fails.** Pending saves now persist delivery status, attempt metadata, errors, and the created ChatMessage ID. A failed post visibly warns the active GM while leaving the request queued; startup and active-GM handoff retry missing cards. Recovery searches for the request's unique identifier before posting, so a lost delivery-state write cannot duplicate a successful card, and a deleted card is recreated while its save remains unanswered. Code: [runtime.js](scripts/runtime.js), [save-delivery.mjs](tests/save-delivery.mjs).

- [ ] **Honor “Every time this happens” while an earlier save is unanswered.** `requestSave()` calls `hasPending()` before considering the repeat policy, and `hasPending()` is keyed only by creature and Effect Block. A second legitimate Entry/turn/trait event is silently discarded even when the block is configured for every occurrence. Allow distinct pending requests per event (the existing pending IDs and batch IDs can distinguish them), or queue/coalesce them explicitly and explain that behavior in the UI. Code: [runtime.js](scripts/runtime.js).

- [ ] **Run a full recovery pass when active-GM authority changes.** The `userConnected` and `updateUser` hooks only call `reconcileUnfinishedActivations()`. A newly authoritative GM can inherit completed-but-unresolved saves, unfinished end/exit cleanup, disabled zones, overdue durations, orphaned Items, and stale HP baselines without any immediate repair. Add one idempotent authority-handoff coordinator that runs the same recovery set used at startup, with serialization so both hooks cannot run it concurrently. Code: [runtime.js](scripts/runtime.js).

- [ ] **Fix on-exit ownership for multiple Tokens linked to the same Actor.** Conditions and Effect Items are deduplicated on the Actor, but each cleanup record stores only the first Token UUID. When that Token exits, cleanup removes the Actor Item even if another eligible Token for the same Actor remains inside. Track all occupying Token UUIDs or use Actor-level reference counting, and remove an on-exit Item only when no eligible representation of that Actor remains in the Region. Add tests for two linked Tokens entering and leaving in both orders. Code: [runtime.js](scripts/runtime.js).

- [ ] **Include cleanup semantics in Effect Item identity.** `addEffectItem()` treats `zoneUuid + blockId + originalUuid` as a duplicate and ignores outcome/removal policy. Reusing the same Effect UUID in different outcomes with `item-duration`, `on-exit`, or `zone-end` can silently keep the first policy and skip the later application. Either include removal/outcome identity in matching and flags or reject ambiguous duplicate configurations during validation. Code: [runtime.js](scripts/runtime.js), [zone-config.js](scripts/zone-config.js).

- [ ] **Make Shielding Taunt transactional and idempotent.** The new Taunt effect is created before previous Taunts are deleted, and the success chat message is posted after all state changes. Failure while deleting an old effect leaves multiple Taunts; failure posting chat reports the whole action as failed even though the mechanical changes succeeded, encouraging a retry. Add an operation ID, compensate or resume partial cleanup, detect an already-created replacement, and return state-change success with a warning when only chat output fails. Code: [shielding-taunt-worker.js](scripts/shielding-taunt-worker.js), [shielding-taunt.js](scripts/shielding-taunt.js), [worker.js](scripts/worker.js).

### P2 - Functionality and user experience

- [ ] **Define and consistently enforce “Creator only” chat visibility.** Formula-duration messages and module chat alerts honor the setting, but save requests, damage cards, and healing cards are always public. This can reveal a hidden zone's name, DC, results, and target. Centralize a message-recipient policy; for interactive saves, include the creator, active GMs, and authorized target owners as appropriate. Update the builder copy so users know exactly who will see each card. Code: [runtime.js](scripts/runtime.js), [duration-chat.js](scripts/duration-chat.js), [builder.js](scripts/builder.js).

- [ ] **Validate imported activation-choice damage types against PF2e's current catalog.** Shared damage options accept any non-empty strings, and validation checks an activation-choice formula as `untyped`. A malformed or stale import can therefore create a zone successfully and fail only when damage is rolled with the unsupported selected type. Reject unavailable slugs using `CONFIG.PF2E.damageTypes`, while preserving a clear migration error for old presets. Code: [zone-config.js](scripts/zone-config.js), [zone-creation.js](scripts/zone-creation.js).

- [x] **Remove Shielding Taunt's dependency on the active GM viewing the encounter Scene.** Range is now measured from TokenDocument geometry and the owning Scene/grid APIs, retaining the same-scene, footprint, elevation, and range checks without changing the GM's view. Chat speaker attribution also uses the TokenDocument rather than a rendered canvas object. Code: [shielding-taunt-worker.js](scripts/shielding-taunt-worker.js).

- [ ] **Audit and remove unused hard module dependencies.** `advanced-macros`, `pf2e-flatcheck-helper`, and `lib-wrapper` are declared as required and block activation when absent, but the shipped module scripts and API-backed compendium macros contain no runtime references to them. Remove dependencies that are no longer needed, or make optional integrations explicit and feature-gated. Update the manifest smoke test and README at the same time. Code: [module.json](module.json), [module-smoke.mjs](tests/module-smoke.mjs), [README.md](README.md).

A Node 24 launcher isolates the licensed Foundry data, and CI provisions current PF2e/dependencies and runs the suite when protected Foundry download/license inputs are configured. Code: [verify.yml](.github/workflows/verify.yml), [foundry tests](tests/foundry), [foundry-integration.mjs](tools/foundry-integration.mjs).

2. **Improvement: Limit retained runtime history and avoid unchanged writes.** Damage/healing roll caches, resolved-save records, and some applied-item references accumulate for the entire lifetime of a zone. Every state transaction writes the whole payload, and condition changes currently visit and rewrite all module zones even when most have no relevant watcher. For unlimited auras used across sessions, this increases stored data and network traffic. Prune records once no pending save needs them, remove stale Item references, and skip writes when nothing changed. This would improve responsiveness without changing the zone's rules. Code: [runtime.js](scripts/runtime.js).
